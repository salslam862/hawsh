# حوشك 2.10.47 — دورة الحجز والعربون والتسوية المالية

## نطاق الإصدار (خمس مجموعات مترابطة)
1. **حالات الحجز:** ضبط الانتقالات المسموحة من `PENDING` إلى التأكيد/الرفض/الإلغاء، ومن `CONFIRMED` إلى الإتمام/الإلغاء، مع إغلاق الحالات النهائية ومنع إعادة معالجتها.
2. **توافر الأصل:** لا يؤكد الحجز إلا إذا كان الأصل نشطًا ومتاحًا وقت التأكيد؛ إعادة فحص الحالة تمنع الحجز على أصل حُجز أو بيع أو خرج من النظام منذ تقديم الطلب.
3. **العربون والاسترداد:** تسجيل العربون مرة واحدة عند التأكيد، وتسجيل رد العربون كحركة مصروف مستقلة عند إلغاء حجز مؤكد، مع ربط الحركتين بالحجز.
4. **التدقيق المالي:** أضيفت `reservationLifecycleMismatches` إلى نقطة المطابقة لاكتشاف الحجز المؤكد بلا حركة عربون، أو تكرار العربون/الاسترداد، أو عدم تطابق صافي العربون.
5. **اختبارات الانحدار والتنظيف:** اختبار HTTP متكامل لمسار إنشاء الحجز وتأكيده وإلغائه، والتحقق من تحرير الأصل وعدم تكرار حركة الاسترداد؛ رفع رقم الإصدار ومخابئ التخزين المؤقت واستبعاد قاعدة بيانات التشغيل.

## ملاحظات محاسبية
- إلغاء الحجز المؤكد يولّد حركة استرداد للعربون بقيمة العربون المسجل. في التشغيل الحقيقي يجب تنفيذ رد المبلغ للعميل فعليًا وتوثيق وسيلة الرد؛ سجل النظام وحده لا يثبت التحويل النقدي أو البنكي.
- لا يُنشئ إتمام الحجز فاتورة أو حركة مالية جديدة تلقائيًا؛ إصدار الفاتورة وتحصيل الرصيد يظلان عبر المسارات المالية المخصصة لتفادي التكرار.
- الإصدار لا يحذف السجلات التاريخية ولا يعكس الحركات القديمة تلقائيًا.

## تحقق محلي
- `node --check src/server.js`
- `node --check public/app.js`
- `npm test`: 49 اختبارًا ناجحًا، صفر فشل.
- اختبار HTTP شغّل نسخة مؤقتة بقاعدة بيانات اختبار معزولة، وأنشأ أصلًا وحجزًا، أكد الحجز مع عربون، ألغاه، وتحقق من حركة عربون واحدة وحركة استرداد واحدة ومن عودة الأصل إلى `ACTIVE`.
- تم فحص سلامة ملف ZIP بعد بنائه.
